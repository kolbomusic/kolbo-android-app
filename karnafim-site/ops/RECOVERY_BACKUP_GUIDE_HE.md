# גיבוי מוצפן לאתר הקרנפים — הכנה ונהלי שחזור

**סטטוס:** כלי הגיבוי נבדק עם PostgreSQL 18 ומסד נתונים סינתטי, אך אין להתייחס אליו כגיבוי נתוני הייצור לפני חיבור שני סודות והצלחת ריצה אמיתית.

## הגנות שמוטמעות בכלי

- `backup_encrypted.sh` מייצא נתונים רק מכתובת ה-Neon שאומתה כענף הייצור `karnafim-rebuild-20261102` (או מ-`localhost` במצב בדיקות בלבד).
- הנתונים מיוצאים בתוך PostgreSQL 18, ונוצרים מקומית קובצי `pg_dump` בפורמט custom. הקובץ הרגיל נמחק בסיום הריצה; הוא **לעולם לא מועלה** כ-artifact.
- הכלי מחייב סיסמת הצפנה באורך 32 תווים לפחות, מצפין באמצעות GnuPG AES-256, מפענח שוב ובודק התאמה מלאה לקובץ המקורי.
- ארבע טבלאות חיוניות חייבות להופיע בארכיון: חברים, פרסומים, הודעות והצעות תמונות הנצחה. אם חסר משהו או הגיבוי מעל 50MiB — הריצה נעצרת.
- המערכת אינה שולחת דואר, אינה פותחת עמוד גיבוי ציבורי ואינה נותנת גישה חדשה לנתונים פרטיים.

## התנאים להפעלת גיבוי ייצור

חיבור GitHub הזמין לעוזר **אינו מאפשר יצירה או עדכון של GitHub Actions Secrets**. לכן אין להכניס נתוני חיבור או סיסמה בקוד, בהודעת צ'אט, ב-Issue או ב-commit.

יש להגדיר ב-`Settings → Secrets and variables → Actions` שני Repository Secrets בלבד:
1. `KARNAFIM_BACKUP_DATABASE_URL`: מחרוזת חיבור נפרדת לקריאה בלבד אם אפשר, של ענף הייצור המאומת, עם TLS. **לעולם לא לשתף אותה בצ'אט.**
2. `KARNAFIM_BACKUP_PASSPHRASE`: סוד אקראי חזק, עדיף 48 תווים ומעלה, שנשמר גם בכספת נפרדת. אובדן המפתח גורם לאובדן יכולת שחזור מהארכיון.

כשהסודות מוגדרים, אפשר להריץ workflow ידני ומוגבל שעושה checkout לקומיט קבוע שעבר בדיקות. הארכיון המוצפן מוחזק ב-GitHub Actions artifacts עם שמירה קצרה. **המאגר הזה ציבורי**, ולכן לא מספיק להסתמך על הפרטיות של artifact: ההצפנה היא תנאי הכרחי. לצורך גיבוי ארוך טווח עדיף להעביר את הארכיון המוצפן לכספת פרטית הנשלטת על ידי בעל האתר.

## בדיקות לפני שמסמנים הושלם

- הרצת workflow מול ענף הייצור וסיום `success`.
- אימות שקיים artifact מוצפן בלבד ושיש לו קובץ checksum מתאים.
- הורדה, פענוח ושחזור בענף Neon **מבודד** עם אותן טבלאות ותוכן מייצג, ללא הצגת פרטי חברים בדוחות.
- הפעלת תזמון רק לאחר אימות סודות ויעד אחסון מתאים, כדי להימנע מריצות כושלות ומעלויות בלתי צפויות.
- ניטור שוטף של גיל הגיבוי ושל שינויי סכימה. נקודת השחזור `br-divine-pond-baatv6tf` בתוך אותו פרויקט Neon היא אמצעי נוסף, אך לא תחליף לגיבוי מוצפן מחוץ לפרויקט.

## מסירת מיילים

האתר יכול לקבל בקשות חברות במסלול `manual_review` שאינו מצריך דוא״ל יוצא, אבל משלוח אימות אוטומטי מצריך ספק (Brevo או Resend), כתובת שולח מאומתת, מפתח API ובדיקת מסירה אמיתית. אין לקבוע `BARKAN_MAIL_DELIVERY_VERIFIED=1` לפני מבחן מסירה מוצלח, ואין לפרסם סודות בקוד.
